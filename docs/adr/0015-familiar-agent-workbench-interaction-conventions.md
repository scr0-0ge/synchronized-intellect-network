# Follow familiar coding-agent interaction conventions, using OpenCode as the primary inspectable reference

Workbench navigation, Project entry, Agent Session creation, composer behavior, keyboard habits, progress states, and other routine interactions will default to conventions shared by Codex, Claude Code, and OpenCode so experienced users do not need to relearn ordinary workflows. When those products differ or proprietary behavior cannot be inspected precisely, OpenCode is the primary behavior and information-architecture reference, while Codex and Claude Code remain comparison references for familiar expectations.

The standard Project-entry flow offers `Create Project` for a new local directory and `Open Project` for an existing directory before recognizing and selecting that directory as a trusted Project. Reference behavior never overrides the Workbench's runtime-owned opaque authentication, main-owned filesystem acquisition, full-path-private renderer boundary, one-open Project rule, or trusted Project `full-access` policy.

This is behavior-first compatibility, not authorization to copy branding, trade dress, proprietary assets, or an external application's backend architecture. Reusing OpenCode source remains a separate, license-reviewed implementation decision, and a possible future free/open-source release does not authorize Git/GitHub, publication, deployment, or distribution now.
